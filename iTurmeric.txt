## Overview of Modules

### Transport Layer
The transport layer of iTurmeric provides the following features for exchanging data in the form of messages or files [cite: 303, 304]:
* Support for 100+ endpoints, including IBM MQ, TCP/IP, RABBIT MQ, ACTIVE MQ, JMS, REST, SOAP, AS/400 Data Queues, and so on [cite: 305].
* SFTP, FTP, FTPS, and Directory-based file exchange [cite: 306].
* Secure communication using TLS and SSL for wire-level data encryption [cite: 307].
* Digital signing and verification (Support for public and private key management) [cite: 308].
* Support for data confidentiality through AES 256-based symmetric encryption [cite: 309].
* Ability to resend automatically in case of connectivity failures [cite: 310].
* Manual retry of message delivery failures [cite: 311].

### Templates Workbench
The message is the core of iTurmeric [cite: 313]. The applications connected to iTurmeric exchange data in the form of messages [cite: 313]. The message templates workbench provides features to create data models for each business message in an agnostic format [cite: 314]. You can decide the actual format of the message when a business flow is configured in the application [cite: 315].

The template files created using the workbench have the `.ofd` extension (e.g., `Customer Payment.ofd`) [cite: 316]. In iTurmeric, you can create a template manually or import it from another source, such as an XML Schema Definition (XSD) or a JSON Schema Definition [cite: 317].

**Components of a Template:**
A template designed in iTurmeric can contain the following components which can be referred to another template [cite: 318, 319, 333]:
* Namespaces [cite: 320]
* Complex Types [cite: 322]
* Groups [cite: 322]

### API Manager
API management is the process of designing, publishing, documenting, and analyzing APIs in a secure environment [cite: 339, 340]. Through an API management solution, you can ensure that both public and internal APIs are consumable and secure [cite: 341]. Key features include [cite: 342]:
* **Flow Design and Hosting:** Create new business flows using a sophisticated flow modeler and host them on the iTurmeric runtime platform [cite: 343].
* **API Design:** Design, publish, and deploy APIs and record documentation, security policies, descriptions, usage limits, runtime capabilities, and other relevant information [cite: 344].
* **API Store:** Store APIs in a repository or catalog acting as a marketplace where you can expose them to internal and/or external stakeholders, subscribe to them, and obtain support from other users or the community [cite: 345, 346].
* **API Analytics:** Monitor API usage, load transaction logs, historical data, and other metrics that inform both the status and success of the available APIs [cite: 347].

### Flow Modelling and Orchestration
A flow determines the logical sequence of components to be executed when an event occurs in iTurmeric Runtime [cite: 348, 349]. A flow can be attached to internal or external events in the runtime [cite: 350]:
* **External Events:** Represent receiving messages and files from an endpoint, invoking an API by a client, and so on [cite: 351].
* **Internal Events:** Represent timers (specific timings), signals (internal signals within runtime), and so on [cite: 352].

Whenever an event occurs, the runtime executes the attached flow [cite: 353]. A flow defines the sequence of execution of various components (connectors, integration tasks, etc.) [cite: 354]. The advanced drag-and-drop flow modeler allows you to invoke one flow from another and define embedded sub-flows (mainly used for exception and event handling) [cite: 355, 356, 357].

### General Use Cases

## Integration Services
iTurmeric has a built-in enterprise integration platform that allows enterprises to connect applications quickly and easily to exchange data [cite: 367, 368, 369]. It enables easy integration of existing systems regardless of different communication technologies (JMS, RESTful, JDBC, HTTP, SFTP, FTP, etc.) [cite: 370].

### Integration Broker vs. Enterprise Service Bus
* **Integration Broker (IB):** Facilitates point-to-point interactions between applications, communication from one program to another, and integration of independent applications or services at the application layer [cite: 373, 374, 375, 376, 377]. Data flows through a central IB designed for data transformation and transport services [cite: 378]. They simplify integration across systems with different formats but do not facilitate complex integration use cases involving flows between multiple applications, content-based routing, or conditional logic between steps [cite: 379, 380].
